# 客户准入确认层

## 模块职责
客户准入确认层位于渠道接入与 Hermes 接待之间，负责在正式进入接待对话前确认客户身份、租户归属、服务资格，并完成客户绑定。

本模块不负责正式接待回复，不负责任务调度，不负责长期记忆管理。

## 核心功能
1. 接收渠道首条消息后的客户识别请求
2. 判断客户是否已经绑定到某个租户
3. 对未绑定客户下发最小信息确认模板
4. 校验客户是否为平台服务对象
5. 生成并绑定 `tenant_id`、`customer_id`、`profile_id`
6. 将客户写入对应租户人员画像
7. 将通过校验的客户放行到 Hermes 接待链路

## 输入
- `channel`
- `channel_user_id`
- `channel_chat_id`
- `message_id`
- 首条用户消息
- 客户填写的准入模板字段

## 输出
- `admission_status`
- `tenant_id`
- `customer_id`
- `profile_id`
- 是否允许进入接待链路

## 必填模板字段
- `service_code`
- `contact_name`
- `mobile`

说明：

- 首次注册：要求客户填写 `服务识别码 + 用户名称 + 用户电话号`
- 已注册客户：只填写 `服务识别码` 也可直接完成绑定
- `company_name` 允许采集，但不属于当前最小准入必填集

## 状态定义
- `bound`：已绑定，直接进入接待
- `pending_verification`：待确认，需填写模板
- `rejected`：拒绝接入，不进入接待

## 边界说明
本模块不直接调用 Hermes 生成正式回复。

本模块只决定客户是否允许进入接待链路，以及进入哪一个租户上下文。

## 当前规则

- 服务识别码按租户隔离，不同租户不可混用
- 同一客户允许链路并行，但绑定以 `tenant_id + service_code` 为主键归属
- 准入通过后，客户长期记忆写入租户管理中的人员画像
