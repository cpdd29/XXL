# 知识库测试矩阵

更新时间：2026-04-30

## 1. 目标

本矩阵用于阶段 8 测试与验收，以及阶段 9 上线前复核。目标是把“知识同步、两段检索、`knowledge_hits` 注入、租户隔离、运营可观测”覆盖完整。

## 2. 适用范围

- `shared` 通用知识库
- 租户专用知识库
- 接待层 `message_ingestion_service.py` 挂接的知识注入链
- 管理台 `/settings/knowledge`、`/knowledge`、`/intake`
- API：`/knowledge/vaults`、`/knowledge/sync-jobs`、`/knowledge/retrieve`、`/knowledge/retrieval-logs`

## 3. 执行前置条件

1. 至少准备 1 个 `shared` vault 和 2 个租户 vault。
2. 每个 vault 至少包含新增、修改、删除三类 Markdown 样本。
3. 准备 1 组通用问题、1 组租户专用问题、1 组跨租户干扰问题。
4. 确认接待层已启用知识注入能力，且检索失败不会阻断主链。
5. 为每条测试记录执行人、执行时间、环境、证据链接或截图编号。

## 4. 结果判定规则

| 结果 | 定义 |
| --- | --- |
| Pass | 预期结果完全满足，且证据可回放 |
| Blocked | 环境或依赖阻塞，测试结论无效 |
| Fail | 关键预期不满足，需要修复后回归 |

阻断级问题定义：

1. 跨租户命中
2. 同步成功但文档与 chunk 明显缺失
3. `knowledge_hits` 未注入且接待链无降级说明
4. 检索异常直接阻断接待主链

## 6. 发布阻断项

出现以下情况，阶段 9 不允许进入试点上线：

1. `KB-I09` 失败，存在跨租户命中。
2. `KB-I12` 失败，接待链没有稳定注入 `knowledge_hits`。
3. `KB-I13` 失败，知识异常会阻断接待主链。
4. `KB-A02` 与 `KB-A03` 失败，接待质量未体现知识能力。

## 7. 建议执行顺序

1. 先执行 `KB-U01` 到 `KB-U05`。
2. 再执行 `KB-I01` 到 `KB-I14`。
3. 阻断项清零后执行 `KB-A01` 到 `KB-A05`。
4. 试点期按日执行 `KB-O01` 到 `KB-O03`。
