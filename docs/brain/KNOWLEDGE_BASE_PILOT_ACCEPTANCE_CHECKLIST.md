# 知识库试点验收清单

更新时间：2026-04-30

## 1. 使用说明

这份清单不是原则文档，而是试点当天直接照着执行的验收单。

当前试点范围按下面的约束执行：

1. 平台是唯一渠道接入与消息输出方。
2. `Hermes` 只作为外接接待智能体，不直接接任何渠道。
3. 只验收手动同步，不启用定时同步。
4. 只放开 `shared` 通用知识库和 1 个试点租户知识库。

建议参与角色：

1. 平台管理员
2. 接入层研发
3. 知识运营
4. 租户负责人

建议证据留存：

1. 页面截图
2. 接口响应
3. 日志片段
4. 验收结论

## 2. 验收结论规则

| 结果 | 含义 |
| --- | --- |
| Pass | 当前项符合预期，可以进入下一项 |
| Fail | 当前项不符合预期，试点停止推进 |
| Risk | 当前项可继续，但必须记录风险并限定范围 |

一票否决项：

1. 跨租户知识命中
2. `Hermes` 无法正常接待
3. 安全阻断不生效
4. 接待链看不到 `knowledge_hits`

## 7. 阶段 D：安全监听验收

说明：

1. 这一阶段只用内测账号执行。
2. 不要在真实客户群里直接做攻击型测试。

| 编号 | 检查项 | 执行方式 | 预期结果 | 结果 |
| --- | --- | --- | --- | --- |
| D-01 | 输入侧风险阻断 | 发送明显的注入/越权测试语句 | 平台直接阻断，不进入正常接待 |  |
| D-02 | 安全事件可见 | 打开 `/intake` | 可看到 `安全阻断` 事件 |  |
| D-03 | 审计日志可见 | 查看相关审计或运行日志 | 有风险记录、时间、链路信息 |  |
| D-04 | 输出侧风险阻断链存在 | 用受控方式模拟高风险回复 | 平台可阻断输出，不下发到渠道 |  |
| D-05 | 正常消息不误杀 | 发送普通咨询问题 | 正常通过，无误阻断 |  |

阶段通过条件：

1. `D-01`、`D-03`、`D-05` 必须通过。
2. `D-04` 若当天无法做真实模拟，可记为 `Risk`，但必须列入试点后一周内补测项。

2. `E-02` 可以在低峰时段执行，不建议在真实客户时段直接做。

## 9. Go / No-Go 结论

### 9.1 可以进入试点

满足以下条件才允许放量：

1. 阶段 A 到阶段 E 无一票否决项失败。
2. `knowledge_hits` 在接待运营台可稳定观察到。
3. 租户知识与通用知识命中都正常。
4. 安全阻断至少完成一次有效演练。
5. 回滚方式已确认。

### 9.2 暂不进入试点

出现以下任一情况，必须暂停：

1. 出现跨租户命中
2. Hermes 接待不稳定
3. 渠道存在重复回复
4. 安全阻断不生效
5. 验收证据不完整，无法回放问题

## 11. 当前推荐执行顺序

按下面顺序推进，不要跳步：

1. 先做阶段 A
2. 再做阶段 B
3. 再做阶段 C
4. 再做阶段 D
5. 最后做阶段 E

如果你准备开始真实验收，第一轮建议只选 1 个试点租户、1 个渠道、1 个外接 Hermes 实例，不要一开始多租户一起放量。
