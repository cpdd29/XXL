# 知识库上线运营 SOP

更新时间：2026-04-30

## 1. 目标

将知识库能力从“开发可用”推进到“上线可运营”，确保以下约束持续成立：

1. 租户知识与通用知识隔离。
2. 平台是唯一检索入口，`Hermes` 只消费 `knowledge_hits`。
3. 同步失败、检索异常、质量回退都有明确处置路径。

## 2. 适用对象与角色

| 角色 | 主要职责 |
| --- | --- |
| 平台管理员 | 创建或维护 vault、控制同步方式、处理系统级异常 |
| 知识运营 | 维护 Markdown 内容、执行导入前检查、发起手动同步、跟进检索效果 |
| 租户负责人 | 确认租户知识边界、审批试点内容、验收租户回复效果 |
| 接入层运营 | 在 `/intake` 观察知识命中是否影响接待质量，反馈异常样本 |

## 3. 上线范围与入口

前端入口：

- `/settings/knowledge`：知识库管理、同步任务、文档详情
- `/knowledge`：知识树浏览、知识内容抽查
- `/settings/tenants`：租户绑定信息确认
- `/intake`：接待效果与接入事件观察

后端关键接口：

- `GET /knowledge/vaults`
- `POST /knowledge/vaults`
- `POST /knowledge/vaults/{vault_id}/scan-preview`
- `POST /knowledge/vaults/{vault_id}/sync`
- `GET /knowledge/sync-jobs`
- `POST /knowledge/retrieve`
- `GET /knowledge/retrieval-logs`

## 4. 上线前准入条件

满足以下条件后，才允许进入试点上线：

1. 通用知识库与试点租户知识库已经完成目录划分，不混放 Markdown。
2. 每个租户只绑定一个租户专用 vault，`shared` vault 单独维护。
3. 阶段 8 测试矩阵已至少完成一轮，阻断级问题清零。
4. 知识运营已确认 Frontmatter、标签、标题层级符合约定。
5. 接入层已确认 `knowledge_hits` 注入失败时不会阻断主接待链。
6. 平台管理员已确认同步路径、租户绑定、启停状态可审计。

推荐执行的仓内自检：

```bash
python3 backend/scripts/check_production_env_contract.py --strict
python3 backend/scripts/check_persistence_contract.py --strict
python3 backend/scripts/check_scheduler_startup.py
python3 backend/scripts/check_nats_contract.py --strict
python3 backend/scripts/check_memory_governance.py --strict
```

说明：

- 以上自检是上线前环境基线，不替代知识库专项测试。
- 如需 PostgreSQL / NATS 运行态验收，按仓库 README 中的严格模式命令执行。

## 5. 首次上线流程

### 5.1 导入顺序

严格按以下顺序推进：

1. 先导入 `shared` 通用知识库。
2. 完成一次手动同步与抽样检索。
3. 再导入试点租户知识库。
4. 对试点租户做一次端到端接待验收。
5. 最后才开启定时同步。

### 5.2 单个 vault 首次接入步骤

1. 在 `/settings/knowledge` 创建 vault。
2. 确认 vault 类型是 `shared` 或 `tenant`，且租户绑定正确。
3. 触发 `scan-preview`，核对 Markdown 扫描结果、文件数量、目录范围。
4. 发起一次手动 `sync`。
5. 在同步完成后检查文档列表、文档详情、切片结果是否可见。
6. 使用 `POST /knowledge/retrieve` 或管理台检索能力验证命中结果。
7. 到 `/intake` 抽样核对接待场景是否实际消费 `knowledge_hits`。

### 5.3 首次上线验收门槛

至少满足以下结果：

1. `shared` 检索可命中通用问题。
2. 试点租户检索优先命中租户知识，再补充通用知识。
3. 不存在跨租户命中污染。
4. `knowledge_hits` 可在接待链样本中观察到。
5. 同步失败不会导致接待主链不可用。

## 6. 定时同步启用 SOP

首次上线阶段必须先手动同步，确认稳定后再开定时同步。

启用规则：

1. 连续 2 个工作日手动同步无阻断异常。
2. 每次同步后的抽样检索结果稳定。
3. 最近一轮新增、修改、删除都已在平台文档状态中体现。

启用步骤：

1. 记录启用时间、操作者、作用范围。
2. 先只对 `shared` 与试点租户启用。
3. 首次定时执行后，立即检查同步任务状态与失败原因字段。
4. 启用后首日增加人工巡检频次，至少在开始、峰值前、峰值后各巡检一次。

暂停条件：

1. 连续两次定时同步失败。
2. 出现跨租户命中异常。
3. 命中结果与最新文档内容明显不一致。

## 7. 日常知识更新 SOP

### 7.1 更新前

1. 确认本次变更属于 `shared` 还是某个租户专用范围。
2. 检查 Markdown 标题、Frontmatter、标签是否完整。
3. 对高风险知识标明更新时间与责任人。

### 7.2 更新执行

1. 在知识源中新增或修改 Markdown。
2. 对大批量修改先走 `scan-preview`。
3. 发起手动同步。
4. 检查同步任务是否成功。
5. 抽样验证 1 到 3 个高频问题的检索结果。

### 7.3 更新后记录

至少保留以下证据：

1. 变更时间
2. 操作者
3. 变更范围
4. 同步任务编号或截图
5. 抽样问题与命中结果

## 8. 归档与过期处理 SOP

适用场景：

- 业务规则过期
- 产品能力下线
- 租户终止试点
- 重复知识被新版内容替代

处理步骤：

1. 先确认该文档不再作为接待主答复依据。
2. 将文档移动到归档目录或按知识源规范标记归档状态。
3. 触发一次手动同步，确认文档状态与 chunk 结果更新。
4. 对受影响问题执行一次回归检索，避免旧内容继续命中。
5. 在变更记录中注明归档原因与回滚方式。

## 9. 同步失败处理 SOP

### 9.1 分级

| 级别 | 判定标准 | 处理要求 |
| --- | --- | --- |
| P1 | 接待主链异常、跨租户污染、全量检索失效 | 立即停用相关 vault 或暂停定时同步，升级平台主管处理 |
| P2 | 单租户同步失败、通用知识局部缺失、检索结果明显过旧 | 30 分钟内人工复核并补做手动同步 |
| P3 | 个别 Markdown 解析失败、标签异常、低优先级知识缺失 | 当日修复并补充规则说明 |

### 9.2 处置步骤

1. 在 `/settings/knowledge` 或 `GET /knowledge/sync-jobs` 确认失败任务与影响范围。
2. 区分是路径问题、解析问题、租户绑定问题还是存储写入问题。
3. 对 P1 / P2 先暂停定时同步，避免持续写入错误状态。
4. 修正文档或配置后，重新执行一次手动同步。
5. 用 `POST /knowledge/retrieve` 验证修复后的命中结果。
6. 在 `/intake` 抽样检查接待是否恢复正常。

### 9.3 升级条件

出现以下任一情况必须升级到平台主管与接入层负责人共同处理：

1. 跨租户命中
2. `shared` 知识大面积消失
3. `Hermes` 接待回复持续引用陈旧知识
4. 重试两次后仍无法完成同步

## 10. 检索效果复盘 SOP

复盘周期：

- 试点期：每日一次
- 稳定期：每周一次
- 重大知识更新后：变更当日追加一次

复盘样本：

1. 高频咨询问题
2. 最近新增知识对应问题
3. 接待层投诉或转任务样本
4. 空命中与低质量命中样本

复盘维度：

1. 是否先命中租户专用知识
2. 是否存在命中但摘要不可用
3. 是否命中了陈旧文档
4. 是否应补录知识或调整标题 / 标签 / Frontmatter
5. 接待最终回复是否真实利用了 `knowledge_hits`

复盘输出：

1. 需要补录的知识清单
2. 需要调整的标签或目录规则
3. 需要回归验证的问题列表
4. 是否继续扩大租户试点范围

## 11. 试点扩大与回滚规则

扩大前提：

1. 试点租户连续 5 个自然日无 P1 事件。
2. 每日抽样问题均可稳定命中。
3. 接入层运营未发现明显错误引用或回复劣化。

回滚触发：

1. 新租户上线后出现跨租户污染。
2. 定时同步导致大批量旧知识残留或新知识缺失。
3. 接待质量在核心场景明显下降。

回滚动作：

1. 停止新增租户接入。
2. 必要时停用问题 vault。
3. 恢复最近一次稳定知识版本。
4. 重新执行手动同步与回归检索。

## 12. 文档与证据留存

每次上线、灰度、异常处置至少保留以下记录：

1. 操作人
2. 时间
3. 租户范围
4. vault 标识
5. 同步任务结果
6. 检索样本与命中摘要
7. 是否影响接待链

建议统一挂接到阶段 8 测试矩阵执行记录，保证测试、上线、复盘证据可串联。
